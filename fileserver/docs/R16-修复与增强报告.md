# R16 修复与增强报告

日期：2026-10-23
范围：`fileserver/`（工作站服务端 + 静态前端装配 + 办公后端）
验证：`ops/smoke-r16.js`，**80/80 通过**（命令见文末）

---

## 一、先说结论：这套东西之前是「半瘫」的

拿到压缩包后先做的不是改代码，而是把它跑起来、逐个接口打一遍。
结果发现三个**致命**问题，任何一个都足以让人以为「整套系统都是废的」：

| # | 现象 | 根因 | 影响面 |
|---|---|---|---|
| 1 | 打开站点根路径 **404**，只剩 `Not Found` | 部署产物里缺 `public/index.html`。R15 前端在 `public/app/`，但服务端只认 `public/index.html` | **整个界面打不开** |
| 2 | 办公页所有接口 **404** | `lib/routes/office.js` 顶部 `require('/opt/station/dsoffice/lib/store.js')` —— 这是个**绝对路径的外部实现，没随仓库发布**，路由模块加载直接抛错，被注册表吞掉 | 办公（文档/表格/看板/导图/便签/演示/流程/表单/海报）**全部不可用** |
| 3 | 「我的分享」列表 404 | `/api/share/<token>` 的通配路由排在前面，把 `/api/share/list` 当成 token 查了 | 分享功能管理端失效 |

除此之外还有一批「不致命但很难受」的问题：

- 诊断页 `ok:false` 永远红 —— 因为把「没装 Samba」算成了故障；
- 诊断里的「Yjs 中继」探活连的是 **42000**（那是 NFS mount 端口），和真实中继（8082）无关；
- 「新建 Word/Excel」（`/api/office/oo/new`）依赖 `/opt/station/onlyoffice/templates/tpl.docx`，没装就 500；
- 格式转换产物固定写到 `/opt/station/fileserver/data/storage/public/_convert`，换部署目录就炸；
- 静态资源**零压缩、零缓存校验**：主界面 845KB 的 JS 每次刷新都完整重下；
- 旧外壳的 Service Worker 注册在**根作用域**，会把新前端一起接管，长期吃旧缓存；
- 旧办公页数据（`data/docs/*.json`）在新办公页里看不到，等于历史文档「消失」。

## 二、做了什么

### 1. 重建办公后端（本轮最大工作量）

新建 `lib/dsoffice/`（约 2400 行，零第三方依赖），把 `lib/routes/office.js`
所依赖的四个模块全部补齐，并保证**接口契约与原实现一致**：

| 文件 | 职责 |
|---|---|
| `store.js` | 文档库：索引 / 正文 / 版本 / 评论 / 回收站 / @提醒 / 附件 / 旧数据迁移 |
| `live.js` | 实时协同：房间、在线名单、光标、操作应用与广播（SSE） |
| `convert.js` | 导入导出：md/txt/html/csv/json/**docx/xlsx/pdf** 内置生成；soffice/ImageMagick/poppler 可选增强 |
| `templates.js` | 14 套模板（会议纪要、周报、OKR、PRD、复盘、日报、预算表、看板、方案汇报、计划导图、站会便签、入职流程、反馈表单、活动海报） |
| `zip.js` | 极简 ZIP 读写（docx/xlsx 就是 ZIP + XML，不引依赖） |

要点：

- **op 语义与前端逐条对齐**。前端 `public/app` 里有一份本地乐观更新用的 `applyOp`，
  服务端如果只存不应用，刷新就回滚。`live.js` 按同样的语义实现了
  cell / sheet(行列增删、冻结、列宽、批注) / board / mind / note / slide / flow / form / poster，
  包括**插入/删除行列时公式里的 A1 引用平移**（与前端 `eb()` 算法一致，删除越界变 `#REF!`）。
- **正文协同用三段合并**，不是简单覆盖：`textSync` 带 `baseText`，
  与当前内容不一致时做「公共前缀 + 双方新增 + 公共后缀」合并并标 `conflict`，
  **任何一方的输入都不会静默消失**。
- **落盘安全**：临时文件 + rename 原子写；实时操作 400ms 防抖；
  关闭进程时 `flushAll()` 强制刷盘；每篇保留最近 30 个版本。
- **旧数据迁移**：新库为空时自动把旧办公页 `data/docs/<user>.json` 的
  doc/sheet/board 迁到新模型（doc 的 HTML 转纯文本、sheet 的二维数组转 A1 单元格）。
- 导出：docx/xlsx 是**真正能被 Word/Excel 打开的 OOXML**（已用 Python `zipfile` 校验容器完整性）；
  PDF 用内置的 STSong-Light（UniGB-UCS2-H）排版，中文不需要嵌字体；
  装了 LibreOffice 时优先走它做高质量转换，`capability()` 返回真实探测结果，前端据此决定按钮。

`lib/routes/office.js` 改为**优先加载仓库内实现**，只有仓库内不存在时才回退到旧的
`/opt/station/dsoffice/` —— 已经装了老版本 dsoffice 的机器不会被破坏。

### 2. 让站点能打开

- 新增 `public/index.html`：R15 主界面入口，资源路径改写为 `/app/assets/...`。
- `handleStatic` 增加**深链回落**：`/files`、`/office` 这类无扩展名路径刷新时回 `index.html`；
  但 `/games/`、`/apps/`、`/office/`、`/assets/` 等静态子站**不回落**，
  避免把「游戏没安装」的 404 伪装成 200。

### 3. 静态资源性能（手机端体感最明显）

| 改动 | 效果 |
|---|---|
| gzip（文本类、>1KB，按 路径+mtime+size 缓存 32 项） | 主界面 JS **845KB → 254KB（-70%）** |
| 弱 ETag + `If-None-Match` → 304 | 二次打开不再重下 845KB |
| 大文件（>2MB）流式发送 | 不再整份 `readFileSync` 进内存 |
| 带哈希的资源 `Cache-Control: immutable` | 命中浏览器磁盘缓存，连请求都省了 |

### 4. 其余修复

- `/api/share/list` 不再被 token 路由劫持（`create/list/revoke` 显式排除）。
- `/api/office/oo/new`：模板缺失时用内置 OOXML 生成空白 docx/xlsx，不再 500；
  模板目录支持 `OO_TEMPLATE_DIR` / `config.json` 覆盖。
- `_convert` 输出目录改为跟随公共盘根目录，不再写死 `/opt/station/...`。
- 诊断页：`sambDb` / `officeRelay` 标为**可选项**（缺失只算 warning），
  新增 `office` 检查（办公库可读写 + 文档数），中继探活端口改成 8082，
  返回体增加 `failed` / `warnings` 便于前端区分。
- 旧外壳 Service Worker：`nas-shell-v29 → v30`（换缓存桶），
  注册作用域收窄到 `/legacy/`，并主动注销残留的根作用域旧 SW（不误伤游戏缓存 SW）。
- 路由注册表不再把纯数据模块（`games-catalog.js`）当成「加载失败」刷告警。
- 快捷创建带 `template` 时真正套用模板（以前给的是白纸）。

## 四、还没做 / 已知边界

1. **多标签页并发下的 op 排序**：现在是「服务端串行应用 + 广播」，语义为 LWW（最后写入胜），
   没有做 OT/CRDT 变换。表格同一单元格并发编辑仍可能互相覆盖（前端会提示冲突）。
2. **pptx 导出**依赖 LibreOffice；没装时明确报错，不会静默生成坏文件。
3. **PDF 抽文字/缩略图**依赖 poppler（`pdftotext`/`pdftoppm`），扫描件需要 OCR，本轮不做。
4. **前端是构建产物**（`public/app/assets/index-*.js` 已压缩混淆），
   所以这轮的 UI 改动只落在「服务端能喂给它的数据」和「外壳/装配层」，
   组件级视觉改动需要前端源码，仓库里没有。
5. 办公页的「实时多人」目前按**文档**维度做房间；跨文档消息靠 `/api/office/notify` 轮询 + SSE 推送。
6. 部署脚本未包含在内：`public/index.html` 需要在构建后重新生成（当前内容是
   `public/app/index.html` 把相对资源改成 `/app/assets/` 绝对路径）。
