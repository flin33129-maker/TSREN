# R16 修复与增强报告

日期：2026-10-23
范围：`fileserver/`（工作站服务端 + 静态前端装配 + 办公后端）
验证：`ops/smoke-r16.js`，**80/80 通过**（命令见文末）

---

## 一、先说结论：这套东西之前是「半瘫」的

拿到压缩包后先做的不是改代码，而是把它跑起来、逐个接口打一遍。
结果发现三个**致命**问题，任何一个都足以让人以为「整套系统都是废的」：

| # | 现象 | 根因 | 影响面 |
|---|---|---|---|
| 1 | 打开站点根路径 **404**，只剩 `Not Found` | 部署产物里缺 `public/index.html`。R15 前端在 `public/app/`，但服务端只认 `public/index.html` | **整个界面打不开** |
| 2 | 办公页所有接口 **404** | `lib/routes/office.js` 顶部 `require('/opt/station/dsoffice/lib/store.js')` —— 这是个**绝对路径的外部实现，没随仓库发布**，路由模块加载直接抛错，被注册表吞掉 | 办公（文档/表格/看板/导图/便签/演示/流程/表单/海报）**全部不可用** |
| 3 | 「我的分享」列表 404 | `/api/share/<token>` 的通配路由排在前面，把 `/api/share/list` 当成 token 查了 | 分享功能管理端失效 |

除此之外还有一批「不致命但很难受」的问题：

- 诊断页 `ok:false` 永远红 —— 因为把「没装 Samba」算成了故障；
- 诊断里的「Yjs 中继」探活连的是 **42000**（那是 NFS mount 端口），和真实中继（8082）无关；
- 「新建 Word/Excel」（`/api/office/oo/new`）依赖 `/opt/station/onlyoffice/templates/tpl.docx`，没装就 500；
- 格式转换产物固定写到 `/opt/station/fileserver/data/storage/public/_convert`，换部署目录就炸；
- 静态资源**零压缩、零缓存校验**：主界面 845KB 的 JS 每次刷新都完整重下；
- 旧外壳的 Service Worker 注册在**根作用域**，会把新前端一起接管，长期吃旧缓存；
- 旧办公页数据（`data/docs/*.json`）在新办公页里看不到，等于历史文档「消失」。

## 二、做了什么

### 1. 重建办公后端（本轮最大工作量）

新建 `lib/dsoffice/`（约 2400 行，零第三方依赖），把 `lib/routes/office.js`
所依赖的四个模块全部补齐，并保证**接口契约与原实现一致**：

| 文件 | 职责 |
|---|---|
| `store.js` | 文档库：索引 / 正文 / 版本 / 评论 / 回收站 / @提醒 / 附件 / 旧数据迁移 |
| `live.js` | 实时协同：房间、在线名单、光标、操作应用与广播（SSE） |
| `convert.js` | 导入导出：md/txt/html/csv/json/**docx/xlsx/pdf** 内置生成；soffice/ImageMagick/poppler 可选增强 |
| `templates.js` | 14 套模板（会议纪要、周报、OKR、PRD、复盘、日报、预算表、看板、方案汇报、计划导图、站会便签、入职流程、反馈表单、活动海报） |
| `zip.js` | 极简 ZIP 读写（docx/xlsx 就是 ZIP + XML，不引依赖） |

要点：

- **op 语义与前端逐条对齐**。前端 `public/app` 里有一份本地乐观更新用的 `applyOp`，
  服务端如果只存不应用，刷新就回滚。`live.js` 按同样的语义实现了
  cell / sheet(行列增删、冻结、列宽、批注) / board / mind / note / slide / flow / form / poster，
  包括**插入/删除行列时公式里的 A1 引用平移**（与前端 `eb()` 算法一致，删除越界变 `#REF!`）。
- **正文协同用三段合并**，不是简单覆盖：`textSync` 带 `baseText`，
  与当前内容不一致时做「公共前缀 + 双方新增 + 公共后缀」合并并标 `conflict`，
  **任何一方的输入都不会静默消失**。
- **落盘安全**：临时文件 + rename 原子写；实时操作 400ms 防抖；
  关闭进程时 `flushAll()` 强制刷盘；每篇保留最近 30 个版本。
- **旧数据迁移**：新库为空时自动把旧办公页 `data/docs/<user>.json` 的
  doc/sheet/board 迁到新模型（doc 的 HTML 转纯文本、sheet 的二维数组转 A1 单元格）。
- 导出：docx/xlsx 是**真正能被 Word/Excel 打开的 OOXML**（已用 Python `zipfile` 校验容器完整性）；
  PDF 用内置的 STSong-Light（UniGB-UCS2-H）排版，中文不需要嵌字体；
  装了 LibreOffice 时优先走它做高质量转换，`capability()` 返回真实探测结果，前端据此决定按钮。

`lib/routes/office.js` 改为**优先加载仓库内实现**，只有仓库内不存在时才回退到旧的
`/opt/station/dsoffice/` —— 已经装了老版本 dsoffice 的机器不会被破坏。

### 2. 让站点能打开

- 新增 `public/index.html`：R15 主界面入口，资源路径改写为 `/app/assets/...`。
- `handleStatic` 增加**深链回落**：`/files`、`/office` 这类无扩展名路径刷新时回 `index.html`；
  但 `/games/`、`/apps/`、`/office/`、`/assets/` 等静态子站**不回落**，
  避免把「游戏没安装」的 404 伪装成 200。

### 3. 静态资源性能（手机端体感最明显）

| 改动 | 效果 |
|---|---|
| gzip（文本类、>1KB，按 路径+mtime+size 缓存 32 项） | 主界面 JS **845KB → 254KB（-70%）** |
| 弱 ETag + `If-None-Match` → 304 | 二次打开不再重下 845KB |
| 大文件（>2MB）流式发送 | 不再整份 `readFileSync` 进内存 |
| 带哈希的资源 `Cache-Control: immutable` | 命中浏览器磁盘缓存，连请求都省了 |

### 4. 其余修复

- `/api/share/list` 不再被 token 路由劫持（`create/list/revoke` 显式排除）。
- `/api/office/oo/new`：模板缺失时用内置 OOXML 生成空白 docx/xlsx，不再 500；
  模板目录支持 `OO_TEMPLATE_DIR` / `config.json` 覆盖。
- `_convert` 输出目录改为跟随公共盘根目录，不再写死 `/opt/station/...`。
- 诊断页：`sambDb` / `officeRelay` 标为**可选项**（缺失只算 warning），
  新增 `office` 检查（办公库可读写 + 文档数），中继探活端口改成 8082，
  返回体增加 `failed` / `warnings` 便于前端区分。
- 旧外壳 Service Worker：`nas-shell-v29 → v30`（换缓存桶），
  注册作用域收窄到 `/legacy/`，并主动注销残留的根作用域旧 SW（不误伤游戏缓存 SW）。
- 路由注册表不再把纯数据模块（`games-catalog.js`）当成「加载失败」刷告警。
- 快捷创建带 `template` 时真正套用模板（以前给的是白纸）。

# R16.1 「真的跑起来给人看」补丁

日期：2026-10-24
触发：把服务部署起来、用 **jsdom 驱动真实前端产物**逐路由点一遍，而不是只看 curl 是否 200。
结果抓出 3 个「接口全绿、页面照崩」的问题，全部修掉并补了可重复的工具。

## 一、修掉的问题

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 办公页整页白屏：`Cannot read properties of undefined (reading 'docx')` | 前端「导入/导出」弹窗读 `capability().export[fmt]`，后端只给了 `{soffice,imagemagick,...}` 的扁平探测结果，**没有 `export` 这一层** | `convert.capability()` 改为返回 `{ engines, import, export }`，`export` 的键与前端 `FORMATS` 完全对齐（`docx/xlsx/md/txt/html/json/csv/pdf/pptx/png/jpg`），值支持 `true \| 'image-only' \| false`；`/api/office/capability` 同时回显 `engines` 与旧扁平字段，老调用方不炸 |
| 2 | 修完 ① 后同一页继续白屏：`Cannot read properties of undefined (reading 'slice')` | 前端评论面板直接 `c.user.slice(0,1)`、`c.replies.map(...)`，而后端评论对象是 `{cid, by, text, at}` | store 内统一经 `_toPublicComment()` 输出 `{id, user, text, at, resolved, replies[]}`，并把历史数据 `_normalizeComments()` 幂等补齐（旧数据不会因为字段缺失再崩一次） |
| 3 | 办公文档列表「有文件、列表空」/ 列表里的文档点开空白、删不掉 | 索引 `index.json` 与正文 `docs/<id>.json` 分开落盘，进程被 kill 或换目录后会互相错位 | 启动时 `_reconcile()` 自愈：摘掉「索引有、正文没了」的条目，找回「正文在、索引没有」的游离文档，并清理指向不存在文档的评论；只动索引，不删用户数据 |
| 4 | 短命进程（CLI/铺数据脚本）退出后索引丢失 | 索引写盘有 400ms 防抖 | `process.on('exit')` 钩子兜底 `flushAll()` |

## 二、为「演示/预览」加的东西

- **`STATION_EMBED_OK=1` 开关**（默认关闭，正式部署行为完全不变）：

- **`ops/seed-demo.js`**：一条命令把工作区铺成「能给人看」的状态——
  7 篇办公文档（会议纪要 / 路线图 / 预算表带 SUM 公式 / 看板 / 演示 / 导图 / 复盘）、
  公共盘 `项目资料/`、`图片/示例图.png`（手写 PNG，零依赖）、协同板与消息中心数据、一条评论串。
  注意它写的是**真实数据源**（`notify-log.json` / `audit.log` / `board.json` / `office/notify.json`），
  自己编一个 `data/notify.json` 是没用的。
- **`ops/ui-probe.js`**：用 jsdom 把真实前端产物跑起来，逐路由检查「渲染成功 / 是否被 React 错误边界接管 / 运行时异常」。

  补了 `EventSource`（真解析 SSE 帧）、`ResizeObserver`、`matchMedia` 等浏览器桩。
  本轮 16 个路由 **全部渲染正常**。

# R16.2 端口可配 + 受限端口联调

日期：2026-10-24
触发：要把预览挂到 **2049** 上。以前这是「改 PORT 就把 NFS 弄坏」的一件事，这次把它变成正经可配项。

## 一、修掉的问题

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 把主服务改到 2049，NFS 起不来，日志只有一行 socket error | `server.js` 里 FTP/NFS/MOUNT 端口写死 `2121/2049/42000`，和主端口撞车 | 端口进配置：`ftpPort` / `nfsPort` / `nfsMountPort`（或 `ports:{ftp,nfs,mount}`），也支持 `FTP_PORT`/`NFS_PORT`/`NFS_MOUNT_PORT` 环境变量；**与主服务撞端口时自动顺延 +10000 并打印说明**（主服务永远优先） |
| 2 | 「连接服务」页在非默认端口部署里整页飘红 | `lib/routes/smb.js` 用 `httpProbe(8081, ...)`、`tcpProbe(2049/2121/42000)` 硬编码探测 | 改为从 `app.cfg.port` 与 `app.svcs.*`（运行时真实端口）取；卡片上显示的端口也是真实值 |
| 3 | mDNS 广播出去的 `_http._tcp` 永远是 8081 | `lib/mdns.js` 的 `SERVICES` 是常量表 | 改成 `servicesOf(srv)`，按 `cfg.port` 与 `svcs.nfs/ftp` 现算，改端口重启即生效 |
| 4 | 回归脚本打 2049 全组假失败 | Chrome 与 Node 的 `fetch()` 都有一份**受限端口名单**（ERR_UNSAFE_PORT），2049/6000/6667 等在列；`curl` 正常、`fetch` 直接 `bad port` | 新增 `ops/lib/unsafe-port-bridge.js`：检测到受限端口就在 127.0.0.1 起一条**透明 TCP 转发**，脚本照常用 fetch / SSE。`smoke` 与 `ui-probe` 都已接入 |

## 二、现在的端口规则（一目了然）

```
主服务端口      PORT=... / config.json: port           ← 永远优先，谁都不许抢
FTP             ftpPort        (默认 2121)   ┐
NFS             nfsPort        (默认 2049)   ├ 撞主端口 → 自动 +10000，并打印 mount 要带的参数
NFS MOUNT       nfsMountPort   (默认 42000)  ┘
关闭某个协议    protocols: { ftp: false, nfs: false, dlna: false, mdns: false }
```

实测（主服务在 2049）：

```
[NFS] 端口 2049 与本服务端口相同，已顺延到 12049（想换回来：config.json 里设 ports.nfs）
[NFS] 提示：挂载时要带非标准端口 → mount -o port=12049,mountport=42000 <host>:/storage /mnt/nas
附属服务   : FTP:2121  NFS:12049(mount:42000)  S3:/s3  API文档:/api/doc
```

## 三、验证

- `BASE=http://127.0.0.1:2049 … node ops/smoke-r16.js` → **82/82 通过**（脚本自动走本地转发）。
- `node ops/ui-probe.js --routes=/home,/files,/office,/services` → 全部渲染正常。
- `/api/smb/status` 的协议卡片显示真实端口：WebDAV 2049 / NFS 12049 / FTP 2121 / relay 42000。

## 四、给「预览/反代」的提醒（写进文档免得下次再踩）

- **2049 在浏览器的受限端口名单里**：直接 `http://<nas>:2049` 会被 Chrome 拦成 `ERR_UNSAFE_PORT`。
  走 HTTPS 反代（例如预览域名 `https://...:443` 转发到内网 2049）不受影响，因为浏览器看到的是 443。
- 如果只是想在浏览器里直接访问，换个端口（8081/8443 等）就好，一个环境变量的事。
