## 三、P1 清单（按模块汇总）

**认证与授权**（lib/auth / totp / acl / pair / share / quota / ratelimit，146 项断言）
- 口令哈希补**异步 scrypt**：原同步版独占事件循环 50–150 ms，并发 WebDAV 认证即可把整站卡死；注册、登录、管理员改密全部走异步版
- 动态验证码加**重放保护**：服务端传入已用 counter，命中步必须严格大于它，并区分「过期 stale」与「不匹配」
- ACL 主体词汇收敛为 `user:` / `group:` / `guest` / `*`，`resolvePerm` 取**最严**匹配（`*` 与组规则不再互相打架）；`acl.json` 损坏 → `lockdownAcl()` 全 none + 审计告警（fail-closed）
- 分享链接：默认 1 次有效、`maxUses` 夹到 ≤50、按 IP 限速、取件失败归还名额
- 上传配额与限速统一到 `ClientLimiter` / `RequestLimiter`
- 注册口令下限 6 → 10；注册端点加**按 IP 的小时级频率闸门（5 次/小时）**

**AI 子系统**（lib/ai / ai-web / ai-tools / tok，82 项断言）
- 出网闸门挂到建连层（DNS 解析结果逐个校验），拦内网/回环/保留地址/云元数据地址，并处理 6to4/NAT64/Teredo 伪装
- 出网白名单 `AI_WEB_ALLOW_HOSTS`；无 vendored undici 时降级为「再解析 + 比对」
- 写类工具与读类工具显式分离，写工具默认不下发给模型
- 游客视图不再泄露模型文件绝对路径（`/opt/station/models/xxx.gguf`）与后端内网地址

**协议栈**（lib/s3 / ftp / dav / nfs / mdns，20+28+11+22 项）
- S3 SigV4 规范化请求重写 + 凭据强度闸门 + 限速
- FTP 登录失败限速（10 次/5 分钟）与 20/10s 闸门，被动端口范围收紧
- DAV 认证失败不泄漏路径、临时文件用完即删
- NFS 导出固定 public/private/ext，匿名只读，NFS 身份统一为 admin 角色
- mDNS 响应去重与速率限制

**运维与协作**（lib/office-oo / snapshot / dedup / tls / im / tasks / hub / util + cli.js，161 项）
- ONLYOFFICE 回调走**主机白名单**：元数据地址硬拒、私网/回环默认拒、`redirect:manual`、256 MB 上限、destroy-before-unlink
- 快照名拒绝路径穿越（`../`）与斜杠；去重改全量 SHA-256 + 大小校验
- IM 频道 id 改 16 位随机 hex；任务取消后不再落盘；Hub 的 SSE 跨域收敛为同源
- Cookie 解析逐个 try/catch（一个坏 Cookie 不炸整条请求）

- 缩略图临时目录清理

## 七之二、自查中发现并修掉的「自己的问题」

这一轮最后做验收取证时，发现两个自己挖的坑，都已修掉并留下证据：

1. **验收脚本里硬编码了 sudo 口令** —— 脚本要进版本库，写死口令等于把凭据
   又抄进 git 历史，正是本轮要清掉的毛病。已改为 `sudo -n` 免密或
   `SUDO_PW=...` 传入，并**重写了最后两条提交**、对本地与服务器做了
   `reflog expire` + `gc --prune=now`（逐个对象扫描确认 0 命中），
   备份盘上的旧 bundle 也一并删除重建。
2. **取证脚本的断言自己有 bug**：把 UFW 输出格式（`Default: deny (incoming)`）、
   提交前缀匹配（漏了 `ops:`）、注册限速计数（没算上前面那一次注册）都判错了，
   一度报出 5 个假 FAIL。已逐条改成与真实行为一致的判定，
   并把「注册限速」单独拎出来做成**自证**的用例（重启清零后连打 6 次，
   第 6 次必然 429）。

顺带说明：注册限速的计数是**内存态**（`this._registerHits`），进程重启即清零 ——
这是设计如此（限速本就针对短时批量注册），但也意味着重启能绕过，
所以真正的防线仍是前端验证码，而前端源码目前缺失（见残留风险）。
